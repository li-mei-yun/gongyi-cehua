## 第一步：准备一个新的空项目

1. 打开本机 Label Studio（http://localhost:8080），登录或先自行注册。
2. 新建项目，例如“SCU2020 拧紧曲线”。**请使用空项目，不要使用之前手工导入过 3918223 的测试项目。**
3. 在 Settings → Labeling Interface → Code 中，粘贴 `package-scu2020/project_config.xml` 的全部内容，保存。
4. 记下网址里的项目编号：例如 `/projects/3/data` 中的 **3**。不要把曲线编号或任务编号当成项目编号。
5. 右上角账户菜单 → Account & Settings → Access Tokens（名称可能显示 Personal Access Tokens / Legacy Tokens），取得自己的访问令牌。工具支持这两种令牌；个人令牌会自动换取短时 access token。

令牌只在本机 PowerShell 的隐藏输入提示中粘贴，不要发到聊天，也不要写入脚本或截图。工具不会保存令牌；仅向 localhost/127.0.0.1 等本机地址发送数据，绕过系统代理，并拒绝 HTTP 重定向。

## 第二步：先导入首批

打开 PowerShell，复制运行下面整段。它会询问项目编号，随后需要输入 `IMPORT 项目编号` 确认，再在隐藏提示中粘贴令牌。

```powershell
$curvePython = 'C:\Users\MGA\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$curveImporter = 'C:\Users\MGA\Documents\ChatGPT\工艺策划\label-studio-setup\batch-curves\import_batches.py'
$curveProjectId = Read-Host '请输入刚刚新建的空项目编号'
& $curvePython $curveImporter --project $curveProjectId --apply --max-batches 1
```

以上使用已验证存在的本机 Python，不需要另外 pip install。不带 `--apply` 时只是本地文件校验，不联网、不改项目。

导入首批后，在网页确认：

- 曲线显示为两个通道：扭矩、角度。
- 横轴是采样点 ID，不是秒；原始文件没有提供采样周期。
- 两个分类均带入：正常曲线／异常曲线、正常拧紧／复拧。
- 检查已知样例 3918223、异常样例 3918255；复拧样例在后续批次出现时也要检查。

本包没有新增异常区间、过滤负数、平滑、按角度排序或对存储数值取整。

## 第三步：继续剩余批次

首批确认后，在同一个 PowerShell 窗口运行：

```powershell
& $curvePython $curveImporter --project $curveProjectId --apply
```

如果已经关闭窗口，重新运行第二步的前三行，再运行上面的命令。

工具会读同一个项目的进度记录，跳过已经确认成功的批次。每批导入完成后至少间隔 30 秒，39 批完整运行的间隔时间约 19 分钟，再加服务实际处理时间。让 Label Studio、Docker 和当前终端保持运行；不需要重启 Dify。

**不要同时通过网页手工导入同一批数据，不要并行运行两个导入进程，不要删除进度文件。** 首次要求项目为空，续跑要求项目任务数与记录吻合。若项目另外新增或删除过任务，工具会停止，避免把不一致的状态当作正常续跑。

## 中断、超时和错误

- 转换中断：重新执行同一转换命令，利用本地缓存续跑。输入文件、标签或打包参数变化后，应另用新的输出目录。
- 已确认成功的导入批次：续跑时跳过。
- 上传超时、断连或返回的任务／标注数量不符：结果可能不确定，工具保留 `inflight` 状态并停止，**不会自动重发**。请先核对项目内该批任务，不能删除记录后盲目重跑。
- `import-…-project-….json` 是导入进度记录，不是待上传数据，不能导入到 Label Studio。
- `.lock` 表示导入正在执行。若进程异常退出，只有确认进程已经结束、并核对进度记录后，才能清理遗留锁文件。
- 不创建或删除项目、不改项目模板、不读取或修改其它项目。

本工具针对 Community Edition 的同步导入返回值；若服务仅返回异步 import ID，会安全停止，不能把提交成功误当成导入完成。

## 将来处理更多文件

转换程序 `convert.py` 只读 Excel，输出新的导入包。默认路径就是当前这批数据；换目录时修改 `--curves` 与 `--labels`，并使用一个新的 `--output`：

```powershell
& $curvePython 'C:\Users\MGA\Documents\ChatGPT\工艺策划\label-studio-setup\batch-curves\convert.py' --curves 'D:\你的曲线目录' --labels 'D:\你的标签目录\label.xlsx' --output 'C:\Users\MGA\Documents\ChatGPT\工艺策划\label-studio-setup\batch-curves\package-new'
```

实际运行前替换上面示意目录。当前程序要求：单层目录、数字文件名 `.xlsx`、Sheet1、相同四列表头，以及每个文件在标签表中恰好一条记录。遇到不匹配就报告，不默认当成正常曲线、不静默丢弃。若分散在多个子目录或格式不同，需要先调整扫描与映射规则。

导入新包时，在导入命令上增加 `--package '新包目录'`，使用另一个新建空项目。不要把更新后的全集再次导入已有项目，否则会重复；增量更新需要另行设计唯一键对账流程。

## 备份与长期使用

- 当前方案适合先完成本机迁移验证。曲线数组内嵌 JSON，简单但会占用 Label Studio 数据库空间。
- 原始 XLSX、原标签表、导入包，以及 Label Studio 数据目录都应独立备份。数据库运行期间不要简单复制活动中的 SQLite 文件当作可靠备份；应在维护窗口停服务或使用一致性备份工具。
- 正式长期使用、多用户并发或持续积累大量曲线时，建议评估 CSV＋受控源存储／对象存储，以及独立 PostgreSQL。不要直接复用或改动 Dify 的数据库配置。
- `source_labels_code` 与 `source_curve_type` 保存的是原始历史标签。以后人工修改了标签，训练数据应从最新 `annotations.result` 提取，不能使用历史字段代替。
- 本批原始标签分布：正常＋正常拧紧 9,848；异常＋正常拧紧 92；正常＋复拧 3,041。复拧不是异常的同义词。
